CFPB Consumer Complaint Database
public · 160-day window · 8 products · 25 institutions
~86,000 complaints · runs on one free-tier Worker
Source — cron pulls whole days from the public CFPB API, ten weeks behind today, because that is when the records are actually complete
01 · CODE
Ingest
Pull public complaints one whole day at a time, and never write the same row twice.
  • Days read whole — the source silently ignores offsets
  • Content hash: a full re-run writes zero rows
  • Recent days re-fetched daily, settled days cached
KV raw cache → D1 · complaints
02 · CODE
Detect
Plain arithmetic ranks every bucket of bank × product × issue. No model involved.
  • Last 14 days against the previous 60
  • Six signals → one 0–100 priority score
  • Weights declared in one file, not fitted to anything
D1 · alerts + signal contributions
03 · MODEL
Enrich
The model writes up an anomaly the numbers already found. It is never asked whether one exists.
  • Sealed packet: ≤15 complaints, nothing else reachable
  • Every factual sentence cites a complaint id
  • A gate re-checks ids, figures and prohibited claims
Fails the gate → the alert still shows, without the prose
D1 · enrichments
04 · HUMAN
Triage
The analyst commits to a severity before the system will show what the model proposed.
  • Judgement locked first, proposal revealed second
  • Enforced in the API, not just the interface
  • Anchored dispositions are excluded outright
D1 · dispositions (the answer key)
05 · GATE
Evaluate
Human judgements score each prompt and model variant — segment by segment, never on the average.
  • Broken out per product and per signal
  • Ships only if every segment clears the bar
  • Validation failures counted apart from disagreements
D1 · eval_runs → ship / no ship
